## Problem Statement

### 1. 用户问题

购买或收到沉香手串后，用户首先需要确认产品身份、证书、产区和养护方式；完成核验后，还需要一个值得再次打开的品牌服务，用于查看藏品、了解沉香知识和记录个人问帖。

当前需求同时覆盖数字身份、内容服务、AI 对话和个人记录。如果只按页面视觉开发，容易出现手串与证书错配、授权后不恢复原操作、AI 输出越界、历史记录语义混乱，以及原型演示能力被误当成真实线上能力等问题。

### 2. 业务问题

- 单次证书核验缺少复访价值，不能独立支撑长期用户关系。
- 多手串用户会绑定多张证书，个人中心不能继续把“证书数量”直接跳到任意一张证书。
- AI 问帖若被包装成确定性算命或改运工具，会增加平台审核、品牌信誉和用户依赖风险。
- 首页同时承担品牌展示、商品预告、藏品、服务和内容，必须明确主次，避免所有模块等权。
- 商城、真实 NFC、真实微信身份、远程 AI、电子证书和产业园内容均依赖外部系统，需求原型不能用模拟行为替代生产合同。

### 3. Why now

- 首页、问帖、我的、证书、养护、产业园和知识文章的视觉与流程已完成多轮确认，可以进入统一评审。
- 2026-08-28 至 2026-08-31 的客户反馈已显著改变原 2.0 PRD，包括四个根 Tab、滚动首页、多藏品、多证书、纯文字问帖、Profile Banner 和公众号式文章。
- 原 2.0 PRD仍包含语音输入、三 Tab、单证书入口、继续旧对话和传统文化帮助页等过期结论，继续使用会直接造成返工。

### 4. 目标用户

- U1：已购买或收到广垦沉香手串，通过芯片、二维码或微信入口查看产品身份的用户。
- U2：拥有一串或多串已绑定手串，需要查找对应证书和溯源记录的用户。
- U3：希望了解沉香知识、养护方法、产业园和认种服务的普通用户。
- U4：希望以传统文化角度梳理挂心事，并保存问帖记录的微信用户。
- U5：负责品牌内容、证书、产业园资料和 AI 安全审核的运营、客服与内容人员。

### 5. 核心术语

- `当前手串`：本次芯片、二维码或首页上下文明确指向的手串。
- `已绑定手串`：已与当前业务账号建立关系、可从“我的手串”列表访问的手串。
- `数字身份`：手串编号、证书、产区、香韵和签发主体信息；防伪溯源是独立页面展示的本串六站记录。
- `问帖`：用户与 AI传统文化解读 Agent 的一次独立对话。
- `新对话`：每次从首页、根 Tab 或历史详情进入 AI 问事时重新创建的会话，不自动恢复上次聊天。
- `安全转向`：AI 对高风险或越界请求不作结论，改为说明边界并提供现实求助方向。
- `展示型内容`：只供阅读，不提供点赞、评论、分享、收藏、输入或发布操作的内容页面。

## Solution

### 1. 产品定位

产品定位为 `沉香数字身份 + AI传统文化解读 Agent + 广垦沉香内容服务`。

- 信任价值：通过数字身份、证书、溯源、藏品档案和产业园资料说明产品来处。
- 使用价值：通过佩戴养护、沉香知识和公众号式文章提供可持续阅读内容。
- 复访价值：通过 AI 问帖和问帖记录形成个人使用轨迹。
- 品牌价值：通过广垦沉香甄选、认种与产业园内容承接品牌与后续商业化，但 MVP 不建设商城交易。

### 2. 全局产品规则

- 根导航固定为 `首页 / 商城 / 问帖 / 我的`。
- 商城仅显示“即将上线”轻提示，不进入空白页或伪商城。
- 首页是滚动内容页，模块顺序固定，不要求一屏展示全部内容。
- 首页当前手串上下文明确，“证书查询”进入当前手串 P-07，“防伪溯源”进入当前手串 P-17。
- “我的”中的证书入口表达账号拥有的全部手串，必须先进入“我的手串”列表，再进入所选证书。
- 每次进入 AI 问事均开始新对话；历史详情只读，点击后续行动也开启新问帖，不续接旧会话。
- AI 页面只支持文字输入与发送，不支持图片、文件、相机、附件、语音或录音。
- AI 不使用手串编号、材质、产区、年份、证书或香韵推断命运。
- 所有 AI 页面持续展示 `内容由 AI 生成，仅供娱乐参考`。
- Profile 下方只保留 `芯片识别说明`，不展示 `关于传统文化解读`。
- 养护手册与“沉香小知识”文章是两套入口：前者为七则养护指南，后者为公众号式纯阅读文章。
- 证书、档案、产业园、知识文章中的正式事实必须来自可核验数据或已审核内容，客户端和 AI 不得补写缺失事实。
- 原型中的数量、证书、PDF、授权、视频和 AI 回复均为演示数据；生产环境必须接真实接口并呈现真实状态。

### 3. 成功指标

- 身份解析成功率：有效芯片或二维码请求中成功返回当前手串身份的比例，目标不低于 99.5%。
- 证书匹配准确率：从“我的手串”选择后打开对应证书且编号一致的比例，目标 100%。
- 问帖有效完成率：开始新问帖后获得至少一次追问及完整结构化参考的会话比例，目标不低于 70%。
- 授权恢复率：因问帖或记录触发授权后，成功返回原意图的比例，目标不低于 98%。
- 内容到达率：养护、知识文章和产业园入口点击后成功展示正文的比例，目标不低于 99%。
- AI 高风险漏放率：安全评测集中应转向却正常回答的比例，发布门槛为 0 个严重样本。
- 正式上线前由数据负责人确认事件定义、去重主键、统计周期和基线；原型演示数据不进入指标。

### 4. 信息架构

- `首页`：品牌主视觉、AI 主入口、广垦甄选、我的藏品、四项服务、产业园、沉香小知识和版权信息。
- `商城`：仅“即将上线”反馈，不承载商品、购物车、订单或支付。
- `问帖`：进入授权判断后打开新的 AI 对话。
- `我的`：微信账号授权、问帖记录、证书数量和芯片说明。
- `页面 PRD`：仅存在于 React 原型手机模型外；入口为浏览器右侧中部的竖向按钮，打开与消保委参考一致的遮罩和全高字段级抽屉，不属于生产小程序信息架构。

### 5. 核心流程

#### FLOW-01 芯片识别到首页

1. 用户通过 NFC、芯片链接或二维码携带 `scan_token` 打开小程序。
2. 客户端请求手串解析接口，服务端校验凭证、手串和证书状态。
3. 成功后进入 P-01 并建立当前手串上下文；失败进入 P-00，不展示演示身份。
4. 用户从首页查看证书时直接进入当前手串 P-07。

#### FLOW-02 微信授权与意图恢复

1. 用户点击需要账号的问帖或问帖记录。
2. 未授权时打开 P-02 手机内授权层，并保存 `pending_intent`。
3. 用户确认后完成微信业务会话；成功自动执行原意图，失败保留原页面和重试入口。
4. 用户主动点击 Profile 的 `微信授权登录` 时，只切换账号状态，不自动进入其他页面。

#### FLOW-03 新问帖与主动追问

1. 每次进入 P-03 都展示新的空态、广垦沉香 Logo、三个快捷主题和文字输入框。
2. 用户点击快捷主题或输入自由问题后，空态切换为连续消息流。
3. Agent 先追问与当前问题相关的背景点，再在信息充分时输出 `判断 / 提醒 / 建议`。
4. 页面内允许继续对话；离开后再次进入时重新开始新会话。

#### FLOW-04 历史记录与开启新问帖

1. 用户从 `我的 → 问帖记录` 进入 P-05。
2. 点击记录进入 P-06，只读展示历史消息。
3. 点击 `开启新问帖` 创建新 conversation，不向原 conversation 追加消息。

#### FLOW-05 多手串证书

1. Profile 展示 `3 串 / 证书数量` 演示值。
2. 点击进入 P-12 `我的手串`，内容区直接展示手串列表，不展示眉题、大标题或说明。
3. 点击任一手串进入 P-07，对应名称、编号、产区、香韵和时间线随所选记录变化。
4. 从详情返回 P-12，并保留原列表位置。

#### FLOW-06 藏品档案与电子证书

1. 首页“我的藏品”在手串与认种沉香树之间切换。
2. 用户可查看对应 P-13/P-14 档案，也可下载对应演示电子证书。
3. 下载失败时保留页面并提示重试；认种档案的“前往认种”只提示商城即将上线。

#### FLOW-07 内容阅读

1. 首页四项服务分别进入证书查询、七则养护、防伪溯源和认种沉香树。
2. 产业园 Banner 进入 P-15 图文专题，包含规模数据、产业链及六节正文。
3. 首页两条“沉香小知识”进入 P-16 公众号式纯展示文章。
4. `沉香知识` 只展示基础知识；产业源头统一由首页“走进产业园”进入 P-15。

### 7. 页面规格

#### P-00 识别结果页

- 页面目标：无法建立当前手串上下文时给出明确原因和恢复路径。
- 适用角色：匿名用户和已登录用户。
- 页面入口：无 token、解析中、无效 token、撤销证书或网络失败。
- 业务规则：失败状态不得展示演示手串、已核验标签或旧缓存证书。
- 字段与内容：状态标题、说明、request_id、重试、识别说明和人工帮助。
- 操作与结果：重新识别再次解析；查看说明进入 P-11；人工帮助打开已配置客服方式。
- 异常与空状态：网络失败保留重试；客服未配置时只显示 request_id。
- 页面验收：所有失败态可恢复且不会误展示成功身份。

#### P-01 首页

- 页面目标：以广垦沉香品牌内容建立信任，并让用户进入问帖、藏品、证书、养护、知识、认种和产业园。
- 适用角色：匿名用户和已登录用户。
- 页面入口：芯片识别成功、根 Tab `首页` 或小程序常规入口。
- 业务规则：按 `品牌主视觉 → AI 问帖 → 广垦沉香甄选 → 我的藏品 → 四项服务 → 产业园 → 沉香小知识 → 版权` 排列并纵向滚动。
- 字段与内容：品牌与产品信息、AI 主入口、四个甄选项、两件藏品、四项服务、产业园摘要、两篇文章和公司版权。

## User Stories

### 1. P0 用户故事

- `US-001` 作为手串用户，我通过芯片入口只看到凭证对应的真实手串身份。
- `US-002` 作为首页用户，我可以直接查看当前手串证书。
- `US-003` 作为多手串用户，我先选择手串，再查看所选证书，避免错配。
- `US-004` 作为未授权用户，我理解授权用途，授权后能继续刚才的操作。
- `US-005` 作为问帖用户，我每次进入都从新对话开始并可自由输入。
- `US-006` 作为用户，我先收到必要追问，再获得判断、提醒和建议。
- `US-007` 作为隐私敏感用户，我不会被要求上传图片、文件、语音、生辰或精确位置。
- `US-008` 作为回访用户，我可以只读查看历史，并从详情开启新对话。
- `US-009` 作为高风险问题用户，我会收到安全转向和现实求助建议。
- `US-010` 作为内容用户，我可以匿名阅读证书、养护、知识、产业园和文章。

### 2. P1 用户故事

- `US-011` 我可以在手串与认种树之间切换、查看档案并下载对应证书。
- `US-012` 我可以通过产业园的关键数据、产业链及章节正文了解种植、科研、加工、出口与品牌建设。
- `US-013` 我可以像阅读公众号一样浏览知识文章，不被互动控件打断。
- `US-014` 弱网或失败时，我不会丢失已成功内容或刚输入的文字。
- `US-015` 商城未开放时，我能得到明确提示而不会进入伪交易流程。

## Implementation Decisions

### 1. 系统边界

- C1 微信小程序客户端：页面、路由、微信登录、NFC 参数、文字输入、状态和本地安全缓存。
- C2 业务 API：鉴权、手串解析、绑定、证书、内容、会话、记录和埋点。
- C3 AI Orchestrator：输入安全、追问判定、模型调用、结构校验、输出安全和模型日志。
- C4 内容服务：养护、知识、产业园（含产业源头）和文章版本管理。
- C5 文件与媒体：电子证书 PDF、图片和视频；原型静态文件不作为生产数据源。
- C6 外部依赖：微信登录、芯片/NFC、模型供应商和内容审核。

### 2. 功能需求

#### 身份识别

- `FR-ID-001 P0` 客户端必须读取 scan_token 并调用解析接口。
- `FR-ID-002 P0` 服务端必须校验 token、手串、证书和签发主体状态。
- `FR-ID-003 P0` 无效或缺失 token 不得返回演示手串。
- `FR-ID-004 P0` 核验标签必须由服务端按核验强度返回。
- `FR-ID-005 P0` 有效扫描会话查看当前手串证书不得要求业务登录。

#### 登录与权限

- `FR-AUTH-001 P0` 基础登录使用 wx.login code 换取服务端 session。
- `FR-AUTH-002 P0` 基础使用不得强制获取头像、昵称或手机号。
- `FR-AUTH-003 P0` 问帖、问帖记录和账号绑定手串列表要求有效 session。
- `FR-AUTH-004 P0` 登录成功恢复 pending_intent；主动授权只就地更新状态。
- `FR-AUTH-005 P0` 首页、问帖和我的共享同一授权状态。

#### 首页与商城

- `FR-HOME-001 P0` 首页模块顺序必须与 P-01 一致。
- `FR-HOME-002 P0` 首页四项服务依次为 `证书查询 / 佩戴养护 / 防伪溯源 / 认种沉香树`，整格可点击并进入对应目的地；证书查询进入 P-07，防伪溯源进入 P-17。
- `FR-HOME-003 P0` 商城相关入口只能显示统一即将上线提示。
- `FR-HOME-004 P1` 单个模块失败不得阻断首页其他模块。

#### AI 会话

- `FR-AI-001 P0` 每次正常进入 P-03 创建新 conversation，不恢复旧会话。
- `FR-AI-002 P0` Agent 按信息充分度返回 CLARIFY、ANSWER 或 SAFE_REDIRECT。
- `FR-AI-003 P0` ANSWER 包含非空 judgment、reminder 和 suggestion。
- `FR-AI-004 P0` Agent 不得使用手串身份信息作命运推断。
- `FR-AI-005 P0` 页面只允许文字输入与发送，不接受图片、文件或音频。
- `FR-AI-006 P0` 请求中禁止重复提交，失败保留消息与草稿。
- `FR-AI-007 P0` Agent 输出保存模型版本、安全判定和免责声明版本。

#### 历史与证书

- `FR-HISTORY-001 P0` 历史列表按 updated_at DESC 分页。
- `FR-HISTORY-002 P0` 详情按 sequence_no 只读展示消息。
- `FR-HISTORY-003 P0` 详情后续行动创建新 conversation，不复用旧 conversation_id。
- `FR-HISTORY-004 P0` 记录读取校验用户所有权。
- `FR-CERT-001 P0` 账号可绑定多串手串，每串最多关联一个当前有效证书。
- `FR-CERT-002 P0` 列表返回唯一 bracelet_id、certificate_id、名称、编号、规格、图片和状态。
- `FR-CERT-003 P0` 详情按 selected_bracelet_id 读取，禁止复用默认首条数据。
- `FR-CERT-004 P0` 首页 current_bracelet_id 与 Profile selected_bracelet_id 是两个明确上下文。
- `FR-CERT-005 P0` 证书字段缺失不得由客户端或 AI 补写。

#### 内容、藏品与媒体

- `FR-CONTENT-001 P1` 内容必须带 content_version 与 updated_at。
- `FR-CONTENT-002 P1` 内容失败优先显示成功缓存，无缓存时重试。
- `FR-CONTENT-003 P0` 养护手册与保养文章使用不同 content_key 和模板。
- `FR-CONTENT-004 P0` 展示型文章不得渲染互动、输入或发布控件。
- `FR-COLLECTION-001 P1` 手串与认种树档案绑定各自数据和证书文件。
- `FR-COLLECTION-002 P1` 下载失败可重试且不能误报成功。
- `FR-PARK-001 P1` 产业园使用客户提供的文字及内容版本，后续图集与视频须使用已审核真实素材。

### 3. 状态模型

- 会话状态：ANONYMOUS、LOGIN_REQUIRED、AUTHENTICATING、AUTHENTICATED、AUTH_ERROR、SESSION_EXPIRED。
- AI 状态：NEW、SUBMITTING、CLARIFYING、GENERATING、READY、SAFE_REDIRECT、FAILED_RETRYABLE。
- 内容状态：LOADING、READY、STALE_CACHE、ERROR_EMPTY、MEDIA_UNAVAILABLE。
- 任意受保护接口均由服务端再次鉴权，客户端状态不构成权限证明。

### 5. API 合同

#### 通用约定

- 基础路径 `/v1`；UTF-8；时间使用 ISO-8601 UTC 并按 Asia/Shanghai 展示。
- 受保护接口使用 Bearer session_token；写接口支持 Idempotency-Key。
- 成功返回 data 与 request_id；失败返回 code、message、retryable、request_id 和 details。

#### `POST /v1/auth/wechat-session`

- 请求：code、privacy_consent_version。
- 返回：user_id、session_token、expires_at、is_new_user。

#### `GET /v1/bracelets/resolve?scan_token={token}`

- 权限：匿名。
- 返回：bracelet、certificate_summary、verification_label、verification_level 和 scan_session。

#### `GET /v1/users/me/bracelets`

- 权限：已登录。
- 返回：items、next_cursor、has_more；items 含 bracelet_id、certificate_id、display_name、serial_no、spec、thumbnail_url 和 binding_status。

#### `GET /v1/bracelets/{bracelet_id}`

- 权限：有效扫描会话或当前用户已绑定。
- 返回：Bracelet 公开字段和当前证书摘要。

#### `GET /v1/certificates/{certificate_id}`

- 权限：同对应手串读取权限。
- 返回：对应手串的 Certificate（含原件、材质检验字段与原图）与按 `bracelet_id` 隔离、固定六站顺序的 TimelineEvent；原型记录标记 `is_demo=true`，不得混入旧四站历史数据或海南来源，不得跨手串回退或复用。

#### `GET /v1/content/{content_key}`

- content_key：care、knowledge、chip-help、industrial-park、knowledge-authenticity、knowledge-care。
- 权限：匿名。
- 返回：title、hero_image_url、content_version、updated_at 和 sections。

#### `POST /v1/conversations`

- 权限：已登录。
- 请求：entry_source 为 HOME、TAB、HISTORY_EMPTY 或 HISTORY_DETAIL。
- 返回：新的 Conversation；同一 Idempotency-Key 不重复创建。

#### `POST /v1/conversations/{conversation_id}/messages`

- 权限：已登录且为所有者。
- 请求：content 为 1–500 字符，client_message_id 为 UUID。
- 顺序：所有权校验、幂等检查、保存用户消息、输入审核、Agent、输出审核、保存 Agent 消息。

#### `GET /v1/conversations?cursor={cursor}&limit=20`

- 权限：已登录。
- 返回：当前用户会话摘要、next_cursor 和 has_more，按 updated_at DESC。

#### `GET /v1/conversations/{conversation_id}`

- 权限：已登录且为所有者。
- 返回：Conversation 与按 sequence_no ASC 的 messages。
- 不存在与非所有者统一返回 CONVERSATION_NOT_FOUND。

### 6. Agent 与非功能规格

- 输入允许：系统规则、当前新会话消息、当前时间、语言和安全策略版本。
- 输入禁止：手串编号、材质、产区、年份、香韵、证书、openid、手机号、精确地址、生辰、面相和掌纹。
- ANSWER 必须包含 judgment、reminder、suggestion；SAFE_REDIRECT 必须包含现实帮助方向。
- 对确定性预测、改运、医疗、法律、金融、自伤、暴力、隐私和提示词注入按安全策略转向或阻断。
- 首屏可交互 P75 不高于 2.5 秒；身份解析 P95 不高于 1.2 秒；AI 首个可见反馈不高于 1 秒。
- iPhone 与 Pixel 不得横向溢出；触控区域不小于 44×44 CSS px；固定导航和输入区不得遮挡内容。
- 日志不得记录原始 openid、scan_token、会话全文、模型密钥或供应商错误栈。

## Scope Priority

### 1. Must / P0

- 当前手串识别、证书查询与防伪溯源。
- 微信授权、意图恢复和全局授权状态。
- 新问帖、纯文字对话、主动追问、结构化回答和安全转向。
- 问帖记录列表与只读详情。
- 多手串列表与证书一一对应。
- 首页完整模块、四项服务和商城占位边界。
- 免责声明、隐私、权限和关键错误状态。

### 2. Should / P1

- 七则养护、沉香知识和两篇公众号式文章；产业源头合并至产业园。
- 藏品轮播、手串/认种档案、电子证书下载。
- 产业园图文专题、关键数据与产业链展示。
- 内容版本、成功缓存、埋点和双设备可用性。

### 3. Could / P2

- 正式商城、认种购买、更多文章、藏品搜索排序和证书分享。
- 内容、证书、绑定、产业园素材和 AI 质量运营后台。

### 4. 依赖、风险与里程碑

- 芯片与证书：品牌方/供应链；未确认则阻塞身份核验上线。
- 微信登录与类目：小程序负责人；未确认则阻塞授权和问帖。
- AI 模型与安全：AI/安全负责人；未通过评测则阻塞 AI 上线。
- 品牌内容与产业园：内容负责人；未审核则只能使用占位内容。
- 隐私与免责声明：法务；未确认则阻塞授权和会话留存。
- 多证书错配风险：生产必须使用 bracelet_id/certificate_id，不以数组位置作主键。
- 原型误当生产风险：评审逐项标记模拟授权、模拟视频、静态 PDF 和本地 AI 回复。
- M1 需求冻结；M2 数据接口冻结；M3 原生小程序联调；M4 安全内容验收；M5 灰度发布。

## Out of Scope

- 不建设真实商城、商品、购物车、订单、支付、地址、售后或认种购买。
- 不支持图片识别、拍照鉴香、文件上传、语音输入、录音、视频通话或数字人对话。
- 不提供确定性预测、改运、法事、医疗、法律、金融或心理诊断。
- 不支持证书解绑、转赠、交易、公开分享、搜索、筛选或详情内证书切换。
- 不建设点赞、评论、收藏、转发、文章发布或社区能力。
- 不建设完整运营后台；相关能力另立后台 PRD。
- React 原型不包含真实数据库、真实微信授权、真实 NFC、远程 AI 或生产监控。
