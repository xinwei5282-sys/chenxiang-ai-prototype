# 上下文产品文档与 AI 定位调整设计

- 日期：2026-08-24
- 状态：设计方案 A 已确认，待书面规格确认后实施
- 范围：React 原型评审层、开发交付 PRD、项目产品规则

## 1. 目标

本次同时完成两项调整：

1. 删除“AI 自我反思”产品定位，统一为 `AI传统文化解读 Agent` 或页面短名称 `AI问事`。
2. 手机模型外的产品文档抽屉默认展示当前手机页面的对应说明，并保留进入完整 PRD 的能力。

不改变首页、问帖、我的及二级页面的现有视觉结构，也不改变 AI 主动追问、连续对话、语音输入和登录门槛。

## 2. 用户可见文案

- 产品定位：`沉香数字身份 + AI传统文化解读 Agent`。
- 首页业务标签继续使用：`AI传统文化解读`。
- 对话页标题继续使用：`AI问事`。
- Agent 自称继续使用：`AI 问事助手`。
- 统一免责声明：`内容由 AI 生成，仅供娱乐参考`。
- 帮助页不再出现“留给自己思考”“自我反思”等表达，改为解释 `自由提问 → Agent 主动追问 → 获得传统文化角度的判断、提醒与建议`。

安全策略继续保留：不得作确定性命运预测，不得宣称转运，不替代医疗、法律和金融专业意见。删除的是产品命名，不是安全边界。

## 3. 产品文档交互

### 3.1 入口与默认状态

- `产品文档`按钮继续位于手机模型外，不进入小程序信息架构。
- 打开抽屉时读取当前处于顶部的稳定页面 ID，不通过页面标题或可见文案猜测页面。
- 默认进入 `当前页面` 视图。
- 抽屉顶部显示 `当前页面名称 / P 编号 / 开发交付版版本号`。
- 提供 `当前页面 / 完整 PRD` 两个切换项；关闭再打开时重新依据当前页面进入 `当前页面`。

### 3.2 当前页面说明结构

每个页面说明固定包含两层内容。第一层是六项摘要：

1. `页面目的`：该页解决的用户任务。
2. `入口与出口`：从哪里进入，可以去哪里或如何返回。
3. `内容与交互`：页面必须展示的内容、主次行动及关键操作。
4. `状态与权限`：登录、加载、空态、错误、禁用或安全状态。
5. `数据与接口`：依赖的数据实体和 API；纯静态内容页明确标记内容来源。
6. `验收条件`：关联 AC 编号及该页最小通过条件。

第二层是从同一份完整 PRD 自动抽取的本页交付规格：

1. `完整页面规格`：P-xx 页面规格的全部条目。
2. `相关流程与状态`：该页涉及的 FLOW 和客户端状态机。
3. `功能需求`：该页关联的完整 FR 条目与优先级。
4. `数据与接口`：该页依赖的完整 API 合同。
5. `验收用例`：该页关联的完整 AC 条目。

页面摘要和完整交付规格均直接来自开发交付 PRD，并由原型按稳定标题和 FR/AC 前缀抽取；原型不得另写一份会漂移的产品规则。

### 3.3 完整 PRD

- 完整 PRD 视图保留现有目录、Markdown 渲染、章节跳转和独立滚动。
- 从当前页面切换到完整 PRD 时，默认定位到该页面的详细规格；用户仍可使用全局目录浏览其他章节。
- 从完整 PRD 切回当前页面时恢复该页面说明顶部。

### 3.4 未映射和异常

- 页面 ID 没有文档映射时显示 `该页面说明尚未配置`，并提供 `查看完整 PRD`；不得错误展示首页说明。
- 文档加载或解析失败时显示明确错误，不影响手机原型继续操作。
- 抽屉打开期间手机页面发生变化时，当前页面说明同步更新；完整 PRD 模式不强制跳转，避免打断阅读。

## 5. 技术设计

### 5.1 页面识别

- 在每个 app-owned 页面根节点添加稳定属性 `data-product-doc-page`。
- 产品文档层只读取当前 `data-flow-current=true` 场景内的页面标记。
- 登录确认层打开时，其页面标记优先于底层页面；关闭后恢复底层页面。
- 产品文档层通过观察当前 Flow 场景和登录层标记变化更新页面 ID，不修改受保护的 FlowStack 运行时。

### 5.2 文档单一真源

- 将开发交付 PRD 文件改名为不含 `ai-reflection` 的路径。
- PRD 中为 P-01 至 P-12 增加标准化页面说明段落及稳定标题标记。
- 原型继续以 `?raw` 导入同一份 PRD。
- Markdown 解析结果同时支持：完整 blocks、按页面标记切出的摘要和页面规格、按标题抽取的流程/状态/API，以及按前缀过滤的 FR/AC。
- 路由到 P 编号的映射只负责声明关联标题和编号前缀，不复制页面需求内容。

### 5.3 组件边界

- `ProductDocumentReview`：抽屉开关、视图切换、当前页面识别和错误/缺省状态。
- `ProductDocContent`：继续只负责 Markdown blocks 渲染。
- 页面根节点：只提供稳定页面 ID，不感知抽屉开关。
- `AuthorizationSheet`：仅在打开时提供 `authorization-sheet` 标记。

## 6. 验收标准

- 在首页打开产品文档，默认标题为 `P-01 首页`，且只展示首页说明。
- 依次进入证书、养护、知识、农垦故事、我的、问帖记录、详情、芯片说明、传统文化解读和 AI 问事，抽屉均展示对应 P 编号。
- 登录确认层打开时展示 P-02；关闭后恢复原页面说明。
- 当前页面视图可切到完整 PRD，完整 PRD 可切回当前页面。
- 完整 PRD 仍保留现有八个全局目录入口和章节滚动。
- 手机模型、设备选择器、键盘、FlowStack 和页面交互不受影响。
- 全项目活跃真源和用户可见界面不再出现 `自我反思`；历史文件如保留，必须明确为历史且不得被原型加载。
- `npm run check:runtime`、`npm run build` 和全量 Playwright 用例通过。
- iPhone 与 Pixel 真实渲染检查无文档遮挡手机、文字溢出或控制台错误。

## 7. 不在本次范围

- 不开发微信原生小程序、真实 NFC、后端、模型或语音服务。
- 不重新设计首页、我的或 AI 对话视觉。
- 不删除确定性预测、转运、医疗、法律和金融安全规则。
- 不在手机模型内增加产品文档入口。

## 8. 自检结论

- 无 TODO/TBD 占位词。
- 产品命名、免责声明和安全策略边界明确，不再把“自我反思”作为功能或定位。
- 页面识别使用稳定 ID，不依赖文案；登录层优先级明确。
- 页面说明来自同一 PRD，避免双份规格漂移。
- 当前范围可以由一个实现计划完成，不需要拆成独立项目。
