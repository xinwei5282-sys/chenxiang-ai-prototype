# 琼南沉香原型 P0 / P1 UI 修复设计

日期：2026-08-24  
状态：待书面确认  
设计依据：`audit/ui-global-audit-2026-08-24/UI-AUDIT.md`

## 目标

在不重新设计首页、不改变已确认品牌风格的前提下，修复入口承诺与实际去向不一致的问题，补齐偏薄的二级内容页，并提高授权、聊天、触控和小字可读性。

## 范围

本轮只处理走查报告中的 P0 和 P1：

1. 建立真实的问帖记录列表与历史详情流程。
2. 将“我的手串”改为与当前证书去向一致的“本串证书”。
3. 补齐佩戴养护、沉香知识内容。
4. 调整 AI 问事免责声明与结构化答案排版。
5. 精简授权弹层，并让不同入口拥有正确的授权目的文案。
6. 将“芯片识别说明”“关于传统文化解读”改为真正可点击的说明页入口。
7. 提升辅助文字对比度和 Pixel 触控尺寸。

本轮不处理：首页视觉重做、首页新增模块、P2 的云纹 / Hero 状态栏 / Pixel 首页比例、真实微信 SDK、真实后端记录、NFC 能力、原生小程序迁移。

## 方案比较

### 方案 A：补齐真实入口和轻量内容闭环（选定）

新增问帖记录列表、历史详情和两个帮助说明页；使用现有 FlowStack、授权状态、视觉变量和内容页结构。优点是入口语义正确，原型可以完整演示；代价是新增少量页面与测试。

### 方案 B：只改入口名称

把“问帖记录”改成“继续问帖”，“我的手串”改成“本串证书”，不新增页面。实现最快，但会继续缺失已经明确需要的历史记录能力。

### 方案 C：仅做视觉精修

只处理字体、间距、颜色和空白。无法解决入口承诺错误，不符合本轮 P0 优先级。

本设计采用方案 A；若实现期间遇到范围冲突，宁可缩减装饰，也不退回错误入口。

## 信息架构与页面设计

### 1. 我的：记录与管理

- 保留“个人香事档案”身份卡和深绿双入口布局。
- 左侧入口仍名为“问帖记录”，授权后进入新的记录列表。
- 右侧入口改名为“本串证书”，继续进入当前“证书与溯源”页面。
- “芯片识别说明”“关于传统文化解读”由静态行改为完整按钮行，增加右箭头与按下态。

### 2. 问帖记录列表

- 顶栏标题：`问帖记录`。
- 首屏展示一条真实感模拟记录：
  - 标题：`新的合作是否适合推进？`
  - 时间：`三天前`
  - 摘要：`先用七天小目标验证合作可靠性。`
- 列表采用纸张底色、分割线和普通行，不使用卡片网格。
- 点击记录进入历史详情。
- 无真实后端；本轮只有一条本地静态记录，不增加筛选、删除或分页。

### 3. 历史详情与继续追问

- 顶栏标题：`问帖详情`。
- 主体复用 AI 问事的左右对话气泡，展示已完成的两轮问答与结构化回答。
- 历史详情默认只读，不显示输入框。
- 底部提供单一按钮 `继续追问`。
- 点击后进入 `AI问事`，Agent 首条消息明确承接历史：`我们接着上次合作的问题继续聊。你现在最想确认哪一步？`
- 继续追问不要求重新授权，因为用户已在进入记录前完成共享授权。

### 4. 授权弹层

授权弹层继续复用一个组件，但根据入口显示不同目的：

- 首页 CTA / 底部问帖：标题 `登录后开始问帖`。
- 问帖记录：标题 `登录后查看记录`。
- 统一主按钮：`微信授权并继续`。
- 删除弹层内部重复的 `先完成微信授权` 二级标题。
- 保留一段用途说明与一行原型提示；原型提示字号至少 12px，颜色达到普通辅助文字的可读水平。
- 授权完成后必须继续原本意图：开始问帖或打开记录列表。

### 5. AI 问事

- 保持当前原生左右气泡、三个快捷问题和追问逻辑。
- `仅供娱乐与自我反思参考` 从消息流尾部移到固定输入区上方，不再随最新消息向下移动。
- 最终回答仍是一只普通 Agent 气泡；仅将 `判断 / 提醒 / 建议` 三个段首加粗并使用深绿色，不新增结果卡或卦象卡。
- 初始欢迎页不增加新卡片、头像、在线状态或装饰模块。

### 6. 佩戴养护

- 保留当前标题和三条养护内容。
- 在标题区域复用现有手串 3D 素材作为小型题图，控制在标题辅助地位。
- 增加一个低强调“常见误区”收尾说明：频繁上油和密封闷放并不会让香气更好。
- 内容结构继续使用编号、分割线和纸张底色，不新增卡片容器。

### 7. 沉香知识

- 保留当前导语和“琼南农垦沉香”入口。
- 在导语与农垦入口之间增加三个非交互知识段落：
  - `01 沉香如何形成`
  - `02 怎样闻香`
  - `03 常见产区差异`
- 每段使用标题加一行摘要，复用农垦故事页的编号与分割线节奏。
- 不新增三个二级路由，避免再次制造空页面。

### 8. 两个帮助说明页

#### 芯片识别说明

- 顶栏标题：`芯片识别说明`。
- 说明 NFC 轻触、识别后进入手串首页、识别失败时重新贴近三个步骤。
- 明确芯片用于识别身份，不会直接开始问帖。

#### 关于传统文化解读

- 顶栏标题：`传统文化解读`。
- 说明流程为自由提问 → Agent 主动追问 → 给出传统文化角度参考。
- 明确仅供娱乐与自我反思，不构成确定性预测、医疗或转运承诺。

## 视觉与可用性规则

- 延续暖纸色、深绿色、宋体标题与系统正文，不引入新色板。
- 普通正文保持 14–15px；重要辅助文字不低于 12px。
- 低对比灰色统一压深，避免继续使用约 2.6:1 的灰色组合。
- iPhone 保留 44px 触控下限；Pixel 的快捷问题、发送和授权按钮提高到至少 48px。
- 新列表行整行可点击，必须有按下态、右箭头和明确的可访问名称。
- 推入新页面前继续调用现有键盘隐藏与 FlowStack 导航逻辑。

## 组件与数据流

### 新增页面工厂

- `readingRecordsScreen(keyboard)`：问帖记录列表。
- `readingRecordDetailScreen(keyboard)`：历史详情。
- `chipHelpScreen(keyboard)`：芯片识别说明。
- `cultureHelpScreen(keyboard)`：传统文化解读说明。

### 复用与轻量扩展

- `AuthorizationSheet` 增加目的文案参数，不复制授权组件或授权状态。
- `FortuneAgent` 支持可选的初始承接消息；正常新问帖行为保持不变。
- 历史详情使用静态模拟消息数据，与真实聊天状态分离，避免详情页误修改历史。
- 所有页面继续位于 `src/Prototype.tsx` 和 `src/prototype.css`，不改受保护移动运行时。

## 状态与异常

- 未授权进入记录：显示授权弹层，授权后直达记录列表。
- 已授权进入记录：直接打开列表，不重复弹层。
- 记录列表本轮固定一条模拟数据，不实现网络加载、失败或空态。
- 帮助页和内容页均为本地静态内容，不增加加载状态。
- AI 模拟回复仍沿用现有 720ms 思考状态与清理定时器逻辑。

## 验收标准

1. “问帖记录”不再进入新问帖，而是进入记录列表。
2. 历史详情展示完整模拟对话，并可通过“继续追问”进入承接上下文的 AI 对话。
3. “我的手串”改为“本串证书”，去向保持证书页。
4. 两个使用帮助行均可点击并进入对应说明页。
5. 养护与知识页不再出现明显的半屏空白和内容未完成感。
6. 授权弹层无重复标题，按钮统一为“微信授权并继续”，且能恢复原始意图。
7. 免责声明固定在输入区上方，不再处于消息流末尾。
8. 最终回答的三个段首有文字层级，但没有新增结果卡。
9. Pixel 的指定核心控件高度至少 48px，关键辅助文字至少 12px且对比度提高。
10. 首页布局与现有视觉不改变；受保护运行时检查通过。
11. iPhone 与 Pixel 的首页、记录、聊天、我的和内容页均完成真实截图走查。

## 测试策略

- 先在 `tests/prototype-h5.spec.ts` 增加失败测试，再写实现。

- 完成后运行聚焦 Playwright、全量 Playwright、`npm run check:runtime` 与 `npm run build`。
- 用本地浏览器截取 iPhone / Pixel 关键页面与交互状态；看图后至少完成一轮视觉修正。

## 规格自审

- 无 `TODO`、`TBD` 或未定义入口。
- P0 / P1 均有对应页面、交互与验收项。
- 未包含 P2 或真实后端 / 原生小程序能力。
- 授权状态保持单一真源，不为记录流创建第二套登录状态。
- 历史详情与新聊天的读写边界明确。
