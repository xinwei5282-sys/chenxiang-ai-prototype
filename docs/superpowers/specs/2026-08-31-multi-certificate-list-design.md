# 多手串证书列表设计

## 背景与目标

用户购买并绑定多串沉香后，一个账号会拥有多张证书。`我的` 页面不能再把“证书数量”直接等同于某一张证书；点击统计入口后先明确选择手串，再查看其证书与溯源详情，避免把相似手串和证书对应错。

## 已确认路径

`我的 → 证书数量（3 串）→ 我的手串列表 → 证书与溯源详情`

- Profile 的 `证书数量` 入口展示 `3 串`，点击进入列表。
- 首页当前手串的 `证书与溯源` 仍直接进入当前手串详情，因为首页上下文已经明确。
- 详情页暂不增加左右滑动、顶部下拉或相邻证书切换，返回列表后再选，保持认知清晰。

## 列表结构

- 页面标题：`我的手串`。
- 顶部导航标题 `我的手串` 下方直接开始列表，不展示眉题、大标题、数量说明或引导文案。
- 使用三条全宽列表项，不使用卡片网格；每项包含真实产品缩略图、手串名称、证书编号、规格/绑定状态和右侧箭头。
- 列表项整行可点击，触控高度不小于 76px；图片、文字和箭头垂直居中。
- 使用现有产品图片资产，不生成新图，不改变受保护移动运行时。

## 模拟数据

1. 海南琼南沉香手串 · `CX-2018-072` · 18mm · 16颗。
2. 琼南蜜韵沉香手串 · `CX-2024-116` · 16mm · 18颗。
3. 岭南雅韵沉香手串 · `CX-2025-031` · 14mm · 20颗。

三条记录均为已绑定、已核验状态；详情页的名称、编号、产区描述、香韵和时间线必须随所选记录变化。

## 交互与边界

- 点击任意列表项进入对应 `证书与溯源` 详情。
- 详情页返回后回到原列表，不丢失列表位置。
- 不实现购买、解绑、转赠、搜索、排序、证书切换器、后台接口或持久化。
- 继续保留现有证书 PDF、首页当前手串入口和产品文档抽屉行为。

## 验收标准

- Profile 显示 `3 串 / 证书数量`，点击后先出现 `我的手串`，不得直接进入详情。
- 列表恰好展示三条可点击记录，信息与模拟数据一致。
- 第二条记录进入详情后显示 `CX-2024-116` 与对应名称，不复用第一条编号。
- 首页 `证书与溯源` 仍直接进入 `CX-2018-072` 详情。
- iPhone 与 Pixel 宽度无横向溢出，列表与详情可正常滚动并避开固定导航/安全区。
- 相关 Playwright 测试、`npm run check:runtime` 和 `npm run build` 通过，真实渲染经视觉检查。
