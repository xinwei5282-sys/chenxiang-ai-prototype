# 手机模型外产品文档抽屉设计

## 目标

在当前移动端原型之外增加一个评审工具入口，让评审者能边操作手机模型、边查看唯一产品 PRD。产品文档不进入小程序信息架构，不出现在手机屏幕、底部导航或“我的”页面中。

## 已确认方案

采用手机模型外的右侧抽屉方案。

- 页面右上角增加 `产品文档` 按钮，与现有设备切换器处于同一评审工具层。
- 点击后从浏览器右侧展开约 440px 的文档抽屉。
- 手机模型不缩放、不移动，抽屉打开后仍可继续操作原型。
- 不使用手机内浮层、手机内路由或“我的”页面入口。

## 结构与组件

### 1. 外部评审入口

- 入口使用独立的原型评审按钮，视觉保持轻量，避免与小程序按钮混淆。
- 入口节点必须渲染在 `[data-phone-screen]` 之外。
- 按钮提供清晰的 `产品文档` 文本和文档图标，并具备键盘焦点态。

### 2. 右侧抽屉

- 抽屉固定在浏览器视口右侧，而不是设备屏幕或手机 Portal 内。
- 桌面宽度为 440px；窄视口使用 `min(440px, calc(100vw - 24px))`，允许覆盖浏览器评审区域，但仍保持在手机 DOM 外。
- 抽屉不添加阻断手机操作的全屏遮罩。
- 顶部固定显示标题、PRD 状态与关闭按钮；正文区域独立滚动。
- 支持关闭按钮和 `Esc` 关闭；关闭后焦点返回入口按钮。
- 使用语义化 `dialog`/互补区域属性，让读屏能够识别文档面板；由于手机仍可操作，不启用模态焦点锁。

### 3. 文档内容

- 内容直接读取 `docs/codex/prd/2026-08-24-agarwood-digital-identity-ai-reflection-mvp.md`，该文件继续作为唯一产品真源。
- 不在组件中复制一份 PRD 文案。
- 将 Markdown 渲染为标题、段落、列表、链接和行内代码；保留正文原有顺序。
- 抽屉顶部提供简洁目录，可跳转到 `Problem Statement / Solution / User Stories / Implementation Decisions / Testing Decisions / Scope Priority / Out of Scope / Further Notes`。
- 外部链接在新标签页打开，并带安全的 `rel` 属性。

## 技术边界

- 只修改应用自有文件 `src/Prototype.tsx`、`src/prototype.css`、相关测试和本设计规格。
- 不修改受保护的 `PhoneFrame`、设备选择器、状态栏、键盘和其他移动运行时文件。
- 在 `Prototype.tsx` 中通过 React Portal 将评审工具渲染到 `document.body`，从现有手机屏幕 Portal 中逃逸到浏览器层。
- 使用项目内唯一 PRD 的 raw import，构建时将内容包含进原型；Markdown 展示逻辑保持局部、可测试，不引入与业务无关的路由或状态库。
- 所有新增样式使用 `product-doc-review-*` 前缀，避免影响手机内样式。

## 状态与交互

### 关闭状态

- 仅显示手机模型外的 `产品文档` 入口。
- 手机原型行为、设备选择器及页面布局与当前一致。

### 打开状态

- 入口保留；右侧抽屉出现并播放克制的横向进入动效。
- 手机仍可点击、滚动与切换设备。
- 文档滚动与手机滚动相互独立。

### 窄屏状态

- 抽屉宽度自适应，可能覆盖浏览器中的部分手机模型，但不进入手机 DOM，也不改变手机原型尺寸。
- 用户可随时关闭抽屉恢复完整评审视野。

### 内容异常

- PRD 通过构建时 raw import 引入，缺失时构建应失败，而不是在运行时显示空白文档。
- Markdown 中未识别的普通文本仍按安全文本显示，不执行文档内 HTML 或脚本。

## 可访问性

- 入口和关闭按钮具备不小于 40px 的浏览器评审工具热区及可见焦点态。
- 抽屉使用明确标题关联，`Esc` 可关闭。
- 不用颜色单独表达打开状态。
- 正文基础字号不小于 14px，行高不小于 1.65，长文阅读对比度满足常规桌面阅读。
- 尊重 `prefers-reduced-motion`，关闭抽屉动效。

## 测试与验收

1. 浏览器页面可见 `产品文档` 入口，且入口不在 `[data-phone-screen]` 内。
2. 点击入口后，抽屉显示 PRD 标题及所有一级章节。
3. 目录点击能滚动到对应章节。
4. 关闭按钮和 `Esc` 均能关闭，关闭后焦点回到入口。
5. 抽屉打开时，首页、问帖、“我的”和设备切换仍可操作。
6. iPhone 与 Pixel 手机模型的尺寸、位置、运行时完整性测试不回归。
7. `npm run check:runtime`、相关 Playwright 测试和 `npm run build` 通过。
8. 查看至少一张抽屉打开状态的真实渲染截图，确认手机与文档的并列关系、正文可读性和没有样式串扰。

## 非目标

- 不把 PRD做成消费者可见的小程序功能。
- 不提供文档编辑、评论、搜索、版本对比或外部同步。
- 不修改 PRD 内容本身。
- 不改变手机模型、首页或其他业务页面视觉。
